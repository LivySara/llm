## 主动Personal Agent 方向

- 1、现了解的产品 - today.ai、openai dots
- 2、技术栈：大模型 + 向量数据库 + RAG 检索增强 + Agent 规划器 + 记忆分层系统 + 工具调用 + 权限安全层
- 3、难点解决方案：

    **一、3.1 - 解决【长期记忆】：记忆分层架构 + 向量数据库 + RAG**
    
    - 瞬时记忆（会话上下文）：当前对话的内容，直接放在大模型 prompt 窗口里。短期临时信息，对话结束就丢弃
    - 中期记忆（事件 / 任务记忆）：
    ```
    保存最近几周的任务、日程、邮件内容。用**向量数据库（Vector DB）**：
    - 把文本做 Embedding（向量化）；
    - 当 Agent 需要处理当前任务，做**RAG 检索**：根据当前场景，检索出相关的历史信息，再塞进 prompt。
    - 例子：你提到 “去西班牙朝圣”，向量库召回你之前聊过的行程、证件要求。
    ```
    - 长期核心记忆（用户档案）
    ```
    提炼你的稳定偏好：比如 “我讨厌早上 8 点会议、喜欢简洁文档、不吃辣”。
    这一层不是原始文本，是**结构化的用户事实档案**，单独存储。
    > 模型自动做信息摘要、事实抽取，把零散对话提炼成结构化记录；用户可以手动查看、编辑、删除（Today.ai 重点强化这个能力）。
    ```
    
    **痛点 & 局限**
    
    - 向量检索会**召回无关信息**（假阳性），带来幻觉；
    - 记忆自动过期、信息冲突很难自动处理，现在大多靠模型判断，不够稳定；
    - 存储越多，检索成本越高。
    
    **总结**：向量库 + RAG 负责 “回忆事情”；结构化记忆库负责 “记住你这个人”。
    
    **二、3.2 - 解决【意图预判 & 主动触发】：事件流 + 意图分类 + 触发策略引擎**
    
    - 事件订阅层
    ```
    持续监听接入的数据源：日历新增事件、收到新邮件、笔记新增内容。
    每一条新数据 = 一个事件，送入系统。
    ```
    - 意图推理（大模型做事件理解）
    ```
    大模型读取事件，判断：
    - 是否属于用户的任务？
    - 用户潜在目标是什么？
    - 这件事是否需要我主动介入？
    ```
    - 触发规则引擎（关键！防止 AI 瞎打扰）
    ```
    混合两套判断：
    - 硬规则：会议前 24h、1h 这种时间触发；
    - LLM 软判断：这件事重要程度、用户是否需要帮助。输出：要不要主动推送提醒 / 方案。
    ```
    
    **三、3.3 - 解决【多步骤任务规划与执行】：Agent 规划框架 + 工具调用（Tool Calling）**
    
    **总结**：当 Agent 判定要帮你做一件复杂任务，标准框架一般是：**规划 → 工具调用 → 观测结果 → 迭代修正**（ReAct 框架最经典）
    
    - 任务拆解（Planner 规划器）
    ```
    大模型把一个大目标拆成有序子任务。
    > 例：帮我准备朝圣之旅
    > ① 查朝圣路线要求 → ② 整理证件清单 → ③ 提取预订信息 → ④ 生成提醒
    ```
    - 工具调用（Tool Calling）
    ```
    模型调用外部 API：读日历、读邮件、联网搜索。
       - Dots：额外自带**云端沙盒虚拟机**，可以操作浏览器、网页、代码，属于更强的工具。
       - Today.ai：工具以读取类 API 为主（读日历、笔记），缺少网页自动操作能力。
    ```
    - 观察 + 反思（ReAct）
    ```
    执行完一步，拿到结果，判断是否成功，失败则调整方案重试。
    如果任务跨多天，会把中间状态保存，等待下一个事件触发继续执行。
    ```
    
    > 局限：长链路任务很容易**一步错，步步错**。任务越长，失败概率越高。业界现在一般会限制超长任务，或者关键节点强制人工确认。
    
    **四、3.4 - 解决【幻觉 & 安全边界】：事实校验 + 分级权限 + 人类确认机制**
    
    - 事实校验层：模型输出结论前，回查原始数据源（邮件原文、日历原始记录），禁止编造不存在信息；
    - 动作风险分级
    ```
    - 低风险：推送提醒、生成摘要 → 可直接主动发送；
    - 高风险：发邮件、修改文档、提交表单 → **必须弹窗，等待用户手动批准，AI 不能直接执行**；
    ```
    - 审计日志：记录 AI 所有读取、推理、动作，用户可以回看 AI 做了什么。

- 4、完整工作流
```
外部数据源（邮件/日历/笔记）
        ↓
【事件监听】捕捉新信息
        ↓
【记忆检索RAG】从向量库+用户档案，召回你的相关历史信息
        ↓
【LLM意图判断】判断：用户有没有潜在需求？要不要主动出手？
        ↓
如果需要执行任务 →【Planner规划器】拆分成子任务
        ↓
【Tool调用/云端沙盒】一步步执行工具
        ↓
【安全校验】判断风险等级：直接推送 / 请求用户批准
        ↓
执行结果写入【记忆库】，更新用户档案
```
